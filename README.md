# Платформа для краудсорсинга
Локальная платформа для организации разметки датасетов со встроенными механизмами кроссвалидации и пайплайнами.
## Архитектура приложения
Репозиторий спроектирован с соблюдением принципов чистой архитектуры.

***Составление задач***

Задачи группируются в пулл, который в последствии становится доступен для разметки/верификации пользователям. Пуллы создаются путем проектирования пайплайна, где указываются настройки для каждого пулла и его тип.

***Динамическое назначение задач***

По умолчанию задача имеет пустую аннотацию и статус AVAILABLE - такая задача считается доступной для разметки.

Задание является таблицей между пользователем и задачей (assignment). Метод get_next_task выдает пользователю доступную задачу, соответствующую его скиллам. Одна и та же задача не может быть выдана пользователю повторно в рамках пулла. Каждая задача дублируется для выдачи overlap раз.

Задача считается выполненной, если она успешно прошла этап разметки и верификации, получает статус COMPLETED, аннотация заполняется аннотацией разметчика.

***Логика разметки***

Под разметкой подразумевается отправка на бекенд аннотаций в формате coco json. После отправки задание встает в статус PENDING и ожидает верификации от следующих пользователей, а текущий пользователь получает следующее задание.

***Логика верификации (кроссвалидация)***

При переходе задания в стадию PENDING ответ разметчика оценивается верификатормами. 

Успешно выполенным считается задание, для которого на этапе верификации собралось 80%+ ответов true, получает статус APPROVED.

Отклоненным считается задание, для которого на этапе верификации собралось 80%+ ответов false, получает статус REJECTED. 

При достижении порого ниже 80% аннотация считается спорной и отправляется на повторную разметку, получает стасус REJECTED.

***Импорт и экспорт***

Задачи для пуллов берутся из датасетов. Загружать данные можно в формате изображений или видео. При загрузке видео, оно фоном разбивается на кадры и сохраняется в датасет.

При экспорте в фоне собирается файл в формате coco json, экспортируются аннотации выполненных задач.

***Авторизация и регистрация***

Эндпоинты платформы предоставляют доступ для следующих ролей пользователей - ADMIN, CUSTOMER, STUDENT. Авторизация происходит по почте и паролю с помощью jwt-токенов.
## Технологический стек
**Frontend**: React, Konva (для разметки), Bun, Vite

**Backend**: Django, Django-Ninja (REST API)

**База данных**: PostgreSQL

**S3 хранилище**: MinIO

**Фоновые задачи и кэш**: Celery, Redis(кеширование, брокер)

**Инфраструктура**: Docker, Docker-compose, Make, Githab Actions (CI/CD)
## Запуск проекта (локально)
1. Создание и настройка файла .env (пример env.example)
   
2. Запустить проект:
```bash
make up
```
3. Провести миграции:
```bash
make migrate
```
4. Создать суперпользователя для административной панели Django(опционально):
```bash
make createsuperuser
```
